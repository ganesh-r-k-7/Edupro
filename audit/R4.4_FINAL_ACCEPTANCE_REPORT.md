### Previously Failing Tests (3) - Now Fixed

The three test failures in `test_retrain_cli.py` were **introduced in commit 364599d** (the R4.4 commit) and have been fixed:

| Test | Original Failure | Root Cause | Fix Applied |
|------|------------------|------------|-------------|
| `test_run_manual_retrain_success` | `AttributeError: module 'edup.models.retrain' has no attribute 'joblib'` | Tests mocked `edup.models.retrain.joblib.dump` but the module doesn't use joblib; also mocked `load_processed_data` and `train_enrollment_model` at wrong module paths | Fixed mock paths to `edup.data.load_processed_data` and `edup.models.models.train_enrollment_model`; added side effect to create model artifact |
| `test_run_manual_retrain_no_model` | `AttributeError: module 'edup.models.retrain' has no attribute 'train_enrollment_model'` | Same mock path issue | Fixed mock path |
| `test_run_scheduled_retrain_enabled` | `FileNotFoundError: [Errno 2] No such file or directory: 'logs/.retraining.lock'` | `run_scheduled_retrain()` used `config.log_dir` directly without resolving relative to registry dir | Fixed to use `config.resolve_log_dir(registry.registry_dir)` and create directory |

**Evidence these were introduced in R4.4**: Both `src/edup/models/retrain.py` and `tests/test_retrain_cli.py` were created in commit 364599d. Running the tests against the parent commit (cd9d887) also fails because the files don't exist there. The failures are defects in the newly added R4.5 preparation code, not pre-existing issues.

## Model Lifecycle Verification

| Scenario | Behavior |
|----------|----------|
| Registry active model exists | Loads from registry, builds metadata from registry entry |
| No registry model, Phase 1 model exists | Loads `enrollment_model_phase1.pkl` with metadata |
| No compatible model | Health: `degraded`; model-info/predict: 503 |
| Legacy `enrollment_model.pkl` | **Never loaded** (incompatible feature contract) |
| Corrupted artifact | Logs error, sets degraded state, returns 503 |
| Model loaded once | Verified via `test_model_loaded_once_across_requests` |

**Critical Finding**: The legacy `enrollment_model.pkl` (with transaction-level features: PaymentMethod, TransactionMonth, Quarter, IsWeekend, SeasonalityLabel, ExpertiseCategoryMatch) is correctly excluded. The API only loads models compatible with the current course-level feature contract (16 features).
