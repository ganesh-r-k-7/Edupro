## 2. CI Configuration

### 2.1 Workflow File

**Location:** `.github/workflows/ci.yml`

```yaml
name: CI

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  test:
    name: Test (Python 3.11)
    runs-on: ubuntu-latest
    timeout-minutes: 15

    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Set up Python 3.11
        uses: actions/setup-python@v5
        with:
          python-version: "3.11"
          cache: "pip"
          cache-dependency-path: "requirements.txt"

      - name: Install dependencies
        run: |
          python -m pip install --upgrade pip
          pip install -r requirements.txt
          pip install pytest

      - name: Verify key imports
        run: |
          python -c "import pandas; import numpy; import sklearn; import xgboost; import shap; import prophet; import plotly; import streamlit; import joblib; import openpyxl; import matplotlib; import seaborn; import statsmodels; import nbformat; print('All imports OK')"

      - name: Run regression suite
        run: |
          python -m pytest tests -v --tb=short

      - name: Report test summary
        if: always()
        run: |
          echo "=== CI Test Summary ==="
          echo "Python version: $(python --version)"
          echo "Pip packages:"
          pip list | grep -E "pandas|numpy|scikit-learn|xgboost|shap|prophet|plotly|streamlit|joblib"
          echo "Test run completed."
```

### 2.2 Design Decisions

| Decision | Rationale |
|----------|-----------|
| **Python 3.11** | Stable, well-supported LTS version; compatible with all dependencies; matches "Python 3.9 or higher" in README |
| **Single job** | Test suite runs in ~30s locally; no need for matrix or parallelization yet |
| **`pip` cache via `actions/setup-python`** | Built-in caching keyed on `requirements.txt`; no custom cache action needed |
| **Install pytest separately** | Pytest is a test-only dependency, not in `requirements.txt` |
| **Import verification step** | Fails fast if any dependency resolution issue occurs |
| **`--tb=short`** | Keeps CI logs readable while preserving failure context |
| **Summary step with `if: always()`** | Reports Python version and key package versions regardless of pass/fail |

## 4. Skipped-Test Decision: XGBoost

### 4.1 Background

The Phase 3 implementation report noted: "Existing regression suite: 247 passing, 3 skipped due to missing XGBoost in the test environment."

Investigation revealed that tests in the following modules use `pytest.importorskip('xgboost')`:
- `tests/test_training_parity.py`
- `tests/test_feature_consistency_hardening.py`
- `tests/test_training_contract.py`

These tests are skipped **only when XGBoost is not importable**. They are not explicitly marked as skipped.

### 4.2 Decision

**Include XGBoost in CI dependencies.** The `requirements.txt` already specifies `xgboost>=1.7.0`. The CI workflow installs from this file, so XGBoost is available and all 247 tests run.

### 4.3 Justification

- XGBoost is a declared project dependency (used in model training notebooks)
- The skipped tests validate critical training/inference parity and feature consistency
- Excluding XGBoost would weaken the test suite and allow regressions in model-related code
- XGBoost installs reliably on Ubuntu (manylinux wheels available)
- No additional CI complexity: single `pip install -r requirements.txt` covers it

### 4.4 Alternative Considered

**Option:** Keep XGBoost optional and accept skipped tests.  
**Rejected:** The roadmap states "Do not silently ignore failures or weaken tests." Skipping model-parity tests would reduce confidence in train/serve correctness.
