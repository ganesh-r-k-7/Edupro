## 3. Model Metadata System

### 3.1 Schema Design (`src/edup/models/metadata.py`)

**`ModelMetadata` dataclass** with fields:

| Category | Fields |
|----------|--------|
| Identity | `model_name`, `model_type`, `artifact_filename`, `status` |
| Training | `training_date_utc`, `target_variable`, `feature_names`, `feature_order` |
| Data Provenance | `training_data_fingerprint`, `training_data_shape`, `training_data_date_range` |
| Metrics | `metrics` (dict) |
| Environment | `python_version`, `platform`, `library_versions` |
| Integrity | `artifact_sha256`, `artifact_size_bytes` |
| Context | `notes` |

**Status values:** `active`, `legacy`, `retired`, `cached`

**Utility functions:**
- `compute_file_sha256()` — Artifact integrity
- `get_library_versions()` — Environment capture
- `compute_data_fingerprint()` — DataFrame deterministic hash
- `load_model_with_metadata()` — Load model + metadata together
- `validate_model_metadata()` — Schema validation
- `generate_metadata_for_existing_artifacts()` — Bulk generation
- `write_all_metadata()` — Write all metadata files + index
- `_create_model_metadata()` — Internal helper for training functions

### 3.2 Generated Metadata Files

| Artifact | Status | Metadata File | Key Details |
|----------|--------|---------------|-------------|
| `enrollment_model.pkl` | legacy | `enrollment_model_metadata.json` | XGBoost pipeline; transaction-level features; not recommended for inference |
| `revenue_model.pkl` | retired | `revenue_model_metadata.json` | LinearRegression; R²=1.0 (accounting identity); target leakage |
| `preprocessing_pipeline.pkl` | legacy | `preprocessing_pipeline_metadata.json` | ColumnTransformer; same features as legacy models |
| `forecast_results.pkl` | cached | `forecast_results_metadata.json` | Prophet output dict; NOT BACKTESTED; 2025-01 to 2025-12 |

**Index file:** `model_metadata_index.json` — Combined manifest with generation timestamp

### 3.3 Metadata Content Principles

- **No invented historical data**: `training_date_utc` is `null` for legacy artifacts
- **Clear status labels**: `legacy`, `retired`, `cached` — no artifact marked `active` except future Phase 1 models
- **Explicit caveats**: Each metadata `notes` field explains limitations
- **Integrity**: SHA256 hashes for all artifacts
- **Feature traceability**: Feature names match what's in the pickled preprocessor

### 3.4 Training Function Enhancements

**`train_enrollment_model()`** now:
- Generates metadata when a Phase 1 model is saved (`enrollment_model_phase1_metadata.json`)
- Captures training timestamp, CV/test metrics, data fingerprint, library versions
- Status set to `active` for new models that beat baseline

**`audit_revenue_target()`** now:
- Ensures revenue model metadata exists (creates if missing)
- Documents retired status with R²=1.0 explanation
