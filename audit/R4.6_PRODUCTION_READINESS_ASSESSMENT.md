## 1. Current Architecture Overview

### 1.1 API Layer (`src/edup/api/main.py`)
- **Framework:** FastAPI 0.116.0 with Uvicorn
- **Endpoints:**
  - `GET /health` — Basic health check (model availability)
  - `GET /model-info` — Model metadata (safe, no paths/secrets)
  - `POST /predict/enrollment` — Prediction with full validation
  - `GET /model-registry` — List all registry versions
  - `GET /model-registry/{version}` — Get specific version details
  - `GET /` — Root info
- **Model Loading:** Lazy-loaded on startup via lifespan, cached globally
- **Error Handling:** Standardized JSON error responses, no stack traces exposed
- **Validation:** Pydantic models with custom validators (boolean rejection, range checks)
- **Logging:** Module-level loggers via `edup.logging`

### 1.2 Configuration (`src/edup/config.py`)
- Centralized constants for paths, feature columns, categorical domains, binning edges, numeric bounds
- No environment-specific configuration (all hardcoded defaults)
- No authentication, rate limiting, CORS, or host configuration

### 1.3 Model Registry (`src/edup/models/registry.py`)
- File-based registry with JSON index and atomic operations
- Statuses: `candidate`, `approved`, `active`, `rejected`, `archived`, `legacy`, `cached`, `retired`
- Lock-based concurrency control
- Promotion workflow: register → validate → approve → promote
- Rollback capability
- Retraining configuration persistence

### 1.4 Streamlit Dashboard (`app/`)
- `app.py` — Main dashboard with multiple pages
- `utils.py` — Shared utilities, data loading, prediction functions
- Shares feature engineering with API via `edup.features`

### 1.5 CI/CD (`.github/workflows/`)
- `ci.yml` — Runs tests, ruff, mypy on push/PR
- `retrain.yml` — Scheduled/manual retraining with candidate validation

3. **Path Safety:** No filesystem paths exposed in API responses

## 5. Key Design Decisions

1. **Authentication:** Optional API key via header (`X-API-Key`), disabled by default for local development
2. **Rate Limiting:** Token bucket algorithm, configurable via env vars
3. **Configuration:** Pydantic Settings with `.env` support, validated at startup
4. **Logging:** JSON format in production, human-readable in development
5. **Health Checks:** Separate liveness (process alive) and readiness (can serve predictions)
6. **Docker:** Multi-stage build, install package in development mode, non-root user
