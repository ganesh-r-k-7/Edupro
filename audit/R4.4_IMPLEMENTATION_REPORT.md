## 1. Architecture Overview

The Enrollment Prediction API is implemented as a FastAPI application under `src/edup/api/`, cleanly separated from the Streamlit dashboard code. The API reuses all existing model loading, feature engineering, validation, and logging infrastructure from the shared `src/edup/` package.

### Key Design Decisions

| Decision | Rationale |
|----------|-----------|
| FastAPI + Uvicorn | Modern, async-capable, automatic OpenAPI docs, Pydantic integration |
| Separate `src/edup/api/` module | Keeps API logic independent of Streamlit UI; enables independent testing |
| Reuse `edup.features` for validation & feature engineering | Guarantees train/serve parity with Streamlit predictions |
| Reuse `edup.models.load_model_with_metadata` | Single model-loading implementation; leverages existing caching/metadata |
| Global model state (loaded once per process) | Avoids redundant model loading; follows existing `st.cache_resource` pattern |
| Pydantic models for request/response | Automatic validation, serialization, OpenAPI schema generation |
| Centralized exception handlers | Consistent JSON error responses; no stack traces exposed |

## 2. Endpoints Implemented

### GET /health
- **Purpose:** Liveness/readiness probe
- **Returns:** API status (`healthy`/`degraded`), model availability, model name, model version
- **Behavior:** Does not reload model; uses cached global state
- **Response Time:** < 1ms (no I/O)

### GET /model-info
- **Purpose:** Safe model introspection
- **Returns:** Model name, type, version (artifact filename), status, feature names, target variable, training date, metrics, notes
- **Security:** No filesystem paths, secrets, or sensitive internal info exposed
- **Error:** 503 if model not loaded

### POST /predict/enrollment
- **Purpose:** Enrollment prediction for a course configuration
- **Input:** Canonical Streamlit form fields (6 required, 3 optional)
- **Validation:** Pydantic + shared `validate_course_inputs` (bounds, enums, Free/Paid logic)
- **Feature Engineering:** Shared `build_feature_frame` + `assert_feature_frame_contract`
- **Prediction:** `model.predict()` on sklearn Pipeline
- **Output:** Predicted enrollment (non-negative), model name, model version, features used
- **Errors:** 400 (validation), 422 (schema), 503 (model unavailable), 500 (internal)

### GET / (Root)
- **Purpose:** API discovery
- **Returns:** Name, version, links to docs, health, model-info, predict

## 6. Limitations & Known Issues

| Limitation | Impact | Mitigation |
|------------|--------|------------|
| Model does not beat mean baseline | Predictions no better than historical average | Documented in `/health`, `/model-info`, and prediction response; dashboard shows reference instead |
| Legacy model artifact used (no Phase 1 model persisted) | Phase 1 model not saved because it doesn't beat baseline | API gracefully falls back to legacy `enrollment_model.pkl` with metadata |
| No authentication / rate limiting | Not production-ready for public exposure | Documented; intended for internal/research use |
| No HTTPS termination | Requires reverse proxy for TLS | Standard deployment practice (nginx, Traefik, etc.) |
| Python 3.14 runtime | pydantic-core wheel only available for 3.14 via manual install | Lock file pins compatible versions; CI uses 3.12 |
