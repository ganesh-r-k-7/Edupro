## 9. Docker Usage

### Build
```bash
docker build -t edupro-api .
```

### Run (Development)
```bash
docker run -d -p 8000:8000 \
  -e ENVIRONMENT=development \
  -e AUTH_ENABLED=false \
  -e RATE_LIMIT_ENABLED=false \
  -v $(pwd)/data:/app/data:ro \
  -v $(pwd)/models:/app/models \
  edupro-api
```

### Run (Production)
```bash
docker run -d -p 8000:8000 \
  -e ENVIRONMENT=production \
  -e AUTH_ENABLED=true \
  -e API_KEYS="<key1>,<key2>" \
  -e RATE_LIMIT_ENABLED=true \
  -e CORS_ORIGINS="https://app.example.com" \
  -e TRUSTED_HOSTS_ENABLED=true \
  -e TRUSTED_HOSTS="api.example.com" \
  -e LOG_FORMAT=json \
  -e LOG_LEVEL=INFO \
  -v /persistent/data:/app/data:ro \
  -v /persistent/models:/app/models \
  edupro-api
```

## 13. Known Security Limitations

| Limitation | Risk | Mitigation |
|------------|------|------------|
| In-memory rate limiting | Doesn't scale across replicas | Use Redis-based rate limiter for production clusters |
| No API key rotation | Long-lived keys | Implement key rotation policy |
| No audit logging | Limited forensic capability | Add audit log middleware |
| No request/response encryption | TLS required at infrastructure | Enforce TLS at load balancer |
| No IP allowlisting | Broad network access | Use network policies / security groups |
| No DDoS protection | Volumetric attacks | Use cloud provider DDoS protection |
| Single-threaded model loading | Startup delay with large models | Pre-warm or use model server |
