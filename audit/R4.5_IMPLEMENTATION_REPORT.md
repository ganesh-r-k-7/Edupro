## 1. Architecture Overview

The R4.5 implementation extends the R4.4 model registry and retraining infrastructure with:

- **Automated GitHub Actions workflow** for scheduled and manual retraining
- **Candidate model validation** with artifact integrity, metadata, feature contract, and performance checks
- **Model registry lifecycle** with statuses: `candidate`, `approved`, `active`, `rejected`, `archived`, `legacy`
- **Controlled promotion** requiring explicit approval before production activation
- **Rollback capability** to any previously approved version
- **Atomic registry operations** with file-based locking
- **Comprehensive test coverage** for all new functionality

## 2. Scheduled and Manual Retraining

### GitHub Actions Workflow (`.github/workflows/retrain.yml`)

| Feature | Implementation |
|---------|----------------|
| **Schedule** | Weekly Sunday 2 AM UTC (`cron: '0 2 * * 0'`) |
| **Manual trigger** | `workflow_dispatch` with inputs: `auto_promote`, `min_r2`, `max_rmse`, `max_mae` |
| **Python** | 3.12 via `actions/setup-python@v5` |
| **Dependencies** | Installed from `requirements.lock` with pip cache |
| **Concurrency** | `concurrency.group: model-retraining`, `cancel-in-progress: false` |
| **Permissions** | `contents: read` (least privilege) |
| **Data validation** | Fails fast if `load_processed_data()` fails |
| **Secrets** | No secrets exposed; no sensitive paths in logs |

### Execution Flow

**Scheduled (cron):**
```yaml
python -m edup.models.retrain scheduled
```
- Uses `RetrainingConfig` from registry (disabled by default)
- Never auto-promotes (`auto_promote=False`)
- Creates candidate model if training succeeds and beats baseline

**Manual (workflow_dispatch):**
```yaml
python -m edup.models.retrain retrain \
  --auto-promote=${{ github.event.inputs.auto_promote }} \
  --min-r2=${MIN_R2} \
  --max-rmse=${MAX_RMSE} \
  --max-mae=${MAX_MAE}
```
- Accepts custom acceptance criteria via inputs
- Optional auto-promotion (default: false)

### Candidate Validation Job

Runs after successful retraining:
1. Checks registry for models with `status == 'candidate'`
2. Validates against `PromotionCriteria` (artifact, metadata, features, metrics, baseline)
3. Fails workflow if validation fails — candidate remains unpromoted

## 3. Candidate Evaluation Criteria

Every new model is registered as a **candidate** and must pass validation before approval.

### Validation Checks (`ModelRegistry.validate_candidate()`)

| Check | Description | Failure Action |
|-------|-------------|----------------|
| **Artifact existence** | File exists in `versions/{version}/` | Reject |
| **Artifact readability** | `joblib.load()` succeeds | Reject |
| **Checksum (SHA256)** | Matches registered `artifact_sha256` | Reject |
| **Metadata existence** | `{artifact_stem}_metadata.json` exists | Reject |
| **Metadata validity** | `validate_model_metadata()` passes | Reject |
| **Feature contract** | `feature_names == FEATURE_COLUMNS` | Reject |
| **Metrics completeness** | `selected_test` has RMSE, MAE, R2 | Reject |
| **Min R²** | `R2 >= criteria.min_r2` (default: -1.0) | Reject |
| **Max RMSE** | `RMSE <= criteria.max_rmse` (default: ∞) | Reject |
| **Max MAE** | `MAE <= criteria.max_mae` (default: ∞) | Reject |
| **Beat baseline** | `RMSE < baseline RMSE` if `must_beat_baseline=True` | Reject |

### Important: No Automatic Promotion

> **EduPro's enrollment model has historically struggled to outperform the mean baseline.** The system **does not manufacture performance improvements** or automatically promote newly trained models. A candidate that fails validation remains in `candidate` status; the existing active model is preserved.

## 4. Model Registry Lifecycle

### Statuses

| Status | Meaning | Transitions |
|--------|---------|-------------|
| `candidate` | Newly registered, awaiting validation | → `approved` (via `approve_candidate`), → `rejected` |
| `approved` | Validated, ready for promotion | → `active` (via `promote`), → `rejected`, → `archived` |
| `active` | Currently serving production predictions | → `legacy` (on new promotion), → `archived` (via rollback) |
| `legacy` | Previously active, available for rollback | → `active` (via `rollback`), → `archived` |
| `rejected` | Failed validation or explicitly rejected | → `archived` |
| `archived` | Retired, not available for activation | (terminal) |
| `cached` | Legacy/compat status (R4.4) | Read-only |

### Registry Operations

All operations are **atomic** (file-based lock + `os.replace`):

```python
# Register new candidate
version = registry.register_model(
    model_name="enrollment_model_candidate",
    model_type="RandomForest",
    artifact_path=Path("model.pkl"),
    status="candidate",  # Always starts as candidate
    training_date_utc="2026-11-25T12:00:00+00:00",
    target_variable="EnrollmentCount (course-level)",
    feature_names=FEATURE_COLUMNS,
    metrics={...},
    training_data=enrollment_df,
)

# Validate candidate
valid, issues = registry.validate_candidate(version, criteria)

# Approve (candidate → approved)
registry.approve_candidate(version, criteria, approved_by="user")

# Promote to production (approved → active)
registry.promote(version, criteria, promoted_by="user")

# Reject (candidate/approved → rejected)
registry.reject_candidate(version, reason="Did not beat baseline", rejected_by="user")

# Rollback to previous version
registry.rollback(target_version)  # or auto-pick most recent legacy

# Archive (non-active → archived)
registry.archive_version(version, archived_by="user")
```

## 5. Controlled Model Promotion

### Promotion Requirements

1. **Explicit approval** — Candidate must be `approved` before promotion
2. **Re-validation** — `promote()` re-runs `validate_candidate()` to ensure criteria still met
3. **Previous active preserved** — Prior active version demoted to `legacy`, not deleted
4. **No automatic replacement** — Production model never replaced without explicit action

### CLI Commands

```bash
# List all versions
python -m edup.models.retrain status

# Approve a candidate
python -m edup.models.retrain approve v20261125_120000_000000

# Promote approved to active
python -m edup.models.retrain promote v20261125_120000_000000

# Reject a candidate
python -m edup.models.retrain reject v20261125_120000_000000 --reason "Failed baseline"

# Archive a version
python -m edup.models.retrain archive v20261125_120000_000000

# Rollback to previous
python -m edup.models.retrain rollback            # Auto-pick most recent legacy
python -m edup.models.retrain rollback v20261125  # Specific version

# Configure scheduled retraining
python -m edup.models.retrain config --enable --schedule "0 2 * * 0" --min-r2 0.0
```

## 11. Remaining Limitations

| Limitation | Notes |
|------------|-------|
| **No auto-promotion in scheduled runs** | By design — `scheduled` command never auto-promotes |
| **Baseline comparison only** | No A/B testing or shadow deployment |
| **Single model type** | Only enrollment model supported; revenue model retired |
| **File-based lock** | Not distributed; suitable for single-runner CI |
| **No model lineage tracking** | Parent/child relationships not recorded |
| **No automated data drift detection** | Retraining runs on schedule regardless of data changes |
| **Manual rollback only** | No automated rollback on prediction anomalies |
